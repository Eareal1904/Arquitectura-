\section{Soporte del Sistema Operativo (Sección)}
\label{sec:org7502a07}

\begin{frame}[label={sec:org2675c70}]{Objetivos del SO (G9, 11, 279)}
\begin{itemize}
\item El sistema operativo (SO) es un programa que controla la ejecución
de aplicaciones y actúa como interfaz entre el usuario y el
hardware.
\item \alert{Comodidad:} Su primer objetivo es hacer que el computador sea más
fácil y cómodo de usar para el usuario final.
\item \alert{Eficiencia:} Su segundo objetivo es administrar los recursos del
sistema de forma eficiente para maximizar su aprovechamiento.
\item Actúa como un mecanismo de control inusual: es un programa que cede
el control del procesador a otras aplicaciones y luego lo recupera
para seguir gestionando el sistema.
\end{itemize}
\end{frame}

\begin{frame}[label={sec:orgb7ec873}]{Funciones del SO relacionadas con memoria (G9, 11, 279)}
\begin{itemize}
\item Existe la  mono pogramacion que se basan en la ejecucion de
un solo proceso hasta que este termine de ejecutarse.
\item La multiprogramacion en cambio trabaja con multiples procesos
consecutivos asignandoles un espacio de memoria y tiempo especificos
para terminar de ejecutarse.
\item \alert{Intercambio (Swapping):} Para evitar que el procesador quede
inactivo, el SO mueve temporalmente al disco los procesos que están
en espera, liberando espacio en memoria principal para nuevos
trabajos.
\end{itemize}
\end{frame}

\section{Planificación y Memoria Virtual (Sección)}
\label{sec:org55b3cc2}

\begin{frame}[label={sec:org8cc1599}]{Planificación de la memoria (G9, 11, 280)}
\begin{itemize}
\item \alert{Particionamiento:} Puede ser fijo (tamaños predefinidos) o dinámico
(asignación exacta requerida). Ambos métodos generan espacios
desperdiciados o fragmentación con el tiempo.
\item \alert{Paginación:} El SO divide la memoria en marcos de tamaño fijo y los
procesos en páginas.
\item \alert{Segmentacion:} El SO divide la memoria en partes de tamaño variable
y tambien los procesos en segmentos con diferentes tipos de
funciones como las principales y las secundarias.
\end{itemize}
\end{frame}

\begin{frame}[label={sec:orge6fbbc4}]{Principios de Memoria Virtual (G9, 11, 282)}
\begin{itemize}
\item Permite ejecutar un proceso sin cargar todas sus instrucciones y
datos en la memoria principal de manera simultánea.
\item \alert{Paginación por demanda:} Las páginas se traen a la memoria solo
cuando se solicitan explícitamente, aprovechando el principio de
localidad.
\item El programador percibe un espacio de memoria enorme (memoria virtual
en disco) sin preocuparse por los límites de la memoria real
(RAM).
\end{itemize}
\end{frame}

\begin{frame}[label={sec:org343d239}]{Paginación (G9, 11, 283)}
\begin{columns}
\begin{column}{0.5\columnwidth}
\begin{itemize}
\item La memoria física se divide en trozos fijos llamados \alert{marcos} (frames).
\item Los procesos se dividen en \alert{páginas} del mismo tamaño.
\item La tabla de páginas mapea cada página virtual a su marco físico.
\item Minimiza el desperdicio de memoria.
\end{itemize}
\end{column}

\section{Traducción de Direcciones (Sección)}
\label{sec:org5977bca}

\begin{frame}[label={sec:orgfd4a117}]{Traducción de direcciones virtuales a físicas (G9, 11, 285)}
\begin{columns}
\begin{column}{0.5\columnwidth}
\begin{itemize}
\item La dirección lógica (virtual) consta de un número de página y un desplazamiento[cite: 1, 2].
\item La dirección física real consta de un número de marco y un desplazamiento[cite: 1, 2].
\item El procesador utiliza la tabla de páginas para producir la dirección física a partir de la lógica[cite: 1, 2].
\end{itemize}
\end{column}

\begin{column}{0.5\columnwidth}
\begin{center}

\end{center}
\end{column}
\end{columns}
\end{frame}

\begin{frame}[label={sec:orge9628ef}]{El Principio de Localidad}
\begin{itemize}
\item Durante la ejecución, los programas confinan su actividad a una pequeña sección del programa o de los datos.
\item Este comportamiento fundamental se conoce como el principio de localidad.
\item Permite cargar solo unas pocas páginas en lugar del proceso entero, haciendo un uso más eficiente de la memoria principal.
\end{itemize}
\end{frame}

\begin{frame}[label={sec:org1b47617}]{TLB (Translation Lookaside Buffer) (G9, 11, 287)}
\begin{itemize}
\item Un esquema de memoria virtual directo duplica el tiempo de acceso a memoria, requiriendo un acceso a la tabla y otro al dato.
\item Para superarlo, se usa un caché especial llamado buffer de traducción anticipada o TLB.
\item El TLB almacena las entradas de la tabla de páginas usadas más recientemente.
\item Debido al principio de localidad, la mayoría de las referencias a memoria encontrarán su traducción rápidamente en el TLB.
\end{itemize}
\end{frame}

\begin{frame}[label={sec:org0c7d005}]{Tabla de Páginas Invertida}
\begin{columns}
\begin{column}{0.5\columnwidth}
\begin{itemize}
\item Es una alternativa para sistemas con enormes espacios de direcciones virtuales.
\item Utiliza una función de dispersión (hash) basada en el número de página virtual.
\item Existe un único elemento en la tabla por cada marco de memoria física real, ahorrando espacio independientemente de los procesos.
\end{itemize}
\end{column}

\end{column}

\end{frame}

\begin{frame}[label={sec:org91a3257}]{Page Faults y reemplazo de páginas (G9, 11, 290)}
\begin{itemize}
\item Con la paginación por demanda, cada página se trae a memoria solo cuando se necesita.
\item Si el procesador hace referencia a una página que no está en memoria principal, se produce un fallo de página (page fault).
\item El SO indica al procesador que lea la página del disco y actualiza la tabla de páginas.
\end{itemize}
\end{frame}

\begin{frame}[label={sec:orgf150743}]{Algoritmos de Reemplazo e Hiperpaginación}
\begin{itemize}
\item Al traer una página nueva a una memoria llena, el SO debe reemplazar (sacar) otra página.
\item Si se expulsa una página que se utilizará casi inmediatamente, el sistema gastará su tiempo intercambiando páginas en lugar de ejecutar código.
\item Esta condición crítica se conoce como hiperpaginación o thrashing.
\item Se busca evitar esto con algoritmos predictivos como el de "menos recientemente usada" (LRU).
\end{itemize}
\end{frame}

\begin{frame}[label={sec:org5c45058}]{Ventajas de la Segmentación}
\begin{itemize}
\item Como ya mencionamos, divide la memoria en espacios dinámicos, pero su gran diferencia es que este esquema suele ser visible para el programador.
\item Simplifica el manejo de estructuras de datos que crecen o se encogen dinámicamente.
\item Facilita la compartición de código y utilidades entre diferentes procesos de forma segura.
\item Permite asignar de manera más natural los privilegios y atributos de protección a cada bloque de memoria.
\end{itemize}
\end{frame}

\begin{frame}[label={sec:org33bed70}]{Segmentación + Paginación (Caso x86/Pentium)}
\begin{itemize}
\item Procesadores como el Intel x86 combinan las ventajas de ambos métodos.
\item El mecanismo de segmentación mapea una dirección virtual a una dirección lineal.
\item Posteriormente, el mecanismo de paginación traduce esa dirección lineal a una dirección física real.
\item El SO gestiona la asignación física de esas páginas en marcos de memoria.
\end{itemize}
\end{frame}

\begin{frame}[label={sec:org87dad53}]{Protección de Memoria y Niveles de Privilegio}
\begin{itemize}
\item El hardware asocia niveles de privilegio y atributos de acceso a cada segmento o página.
\item Existen 4 niveles de privilegio, desde el más protegido (Nivel 0) para control de memoria, hasta el menos protegido (Nivel 3) para aplicaciones.
\item Los atributos especifican permisos como solo lectura o lectura/escritura.
\item Si un programa intenta un acceso no autorizado, el hardware detecta el error y transfiere el control al sistema operativo.
\end{itemize}
\end{frame}

\section{Máquinas Virtuales (Sección)}
\label{sec:org7b6c901}

\begin{frame}[label={sec:org1b852dc}]{¿Qué es una Máquina Virtual? (G9, 11, 292)}
\begin{itemize}
\item Una Máquina Virtual (VM) es un software que simula un computador
completo.
\item Permite ejecutar varios sistemas operativos sobre un mismo hardware físico.
\item Cada sistema operativo invitado cree que posee CPU, memoria y disco propios.
\item El aislamiento permite que cada VM funcione independientemente de las demás.
\end{itemize}
\end{frame}

\begin{frame}[label={sec:org7e44909}]{¿Por qué utilizar Máquinas Virtuales?}
\begin{itemize}
\item Ejecutar varios sistemas operativos simultáneamente.
\item Aprovechar mejor el hardware disponible.
\item Probar software sin afectar el sistema principal.
\item Crear laboratorios y entornos de desarrollo.
\item Ejecutar aplicaciones antiguas o incompatibles.
\end{itemize}
\end{frame}

\begin{frame}[label={sec:org215dc41}]{Host OS y Guest OS (G9, 11, 292)}
\begin{block}{Host OS}
\begin{itemize}
\item Sistema operativo instalado físicamente.
\item Administra el hardware real.
\item Controla CPU, memoria, disco y dispositivos.
\end{itemize}
\end{block}

\begin{block}{Guest OS}
\begin{itemize}
\item Sistema operativo que se ejecuta dentro de una VM.
\item Cree tener acceso exclusivo al hardware.
\item Comparte recursos mediante el hipervisor.
\end{itemize}
\end{block}
\end{frame}

\begin{frame}[label={sec:org60f6bcb}]{Hipervisor: ¿Qué hace?}
\begin{itemize}
\item Es el software encargado de crear y administrar máquinas virtuales.
\item Distribuye CPU, memoria, almacenamiento y red.
\item Aísla las máquinas virtuales entre sí.
\item Permite ejecutar múltiples Guest OS simultáneamente.
\end{itemize}
\end{frame}

\begin{frame}[label={sec:org9dc9b89}]{Hipervisores: Tipo 1 y Tipo 2 (G9, 11, 295)}
\begin{columns}
\begin{column}{0.45\columnwidth}
\begin{itemize}
\item \alert{Tipo 1 (Bare Metal):}
\item Se instala directamente sobre el hardware.
\item Mayor rendimiento.
\item Uso común en centros de datos.

\item \alert{Tipo 2 (Hosted):}
\item Funciona como una aplicación sobre un sistema operativo.
\item Fácil de instalar.
\item Ideal para estudiantes y pruebas.
\end{itemize}
\end{column}

\begin{frame}[label={sec:orgd4e9f64}]{Virtualización de Memoria (G9, 11, 298)}
\begin{itemize}
\item El Guest OS utiliza direcciones virtuales.
\item Estas se convierten en direcciones físicas virtuales.
\item El hipervisor las traduce a direcciones físicas reales.
\item Este proceso permite compartir la memoria de forma segura.
\end{itemize}
\end{frame}

\begin{frame}[label={sec:orgbe50283}]{Aceleración por Hardware}
\begin{itemize}
\item La traducción de memoria puede ser costosa.
\item Los procesadores modernos incorporan soporte para virtualización.
\item Intel utiliza Extended Page Tables (EPT).
\item AMD incorpora tecnologías equivalentes mediante AMD-V.
\item Estas tecnologías reducen la sobrecarga y mejoran el rendimiento.
\end{itemize}
\end{frame}

\begin{frame}[label={sec:org449930e}]{WSL y su relación con las Máquinas Virtuales}
\begin{itemize}
\item WSL permite ejecutar Linux dentro de Windows.
\item WSL 1 no utiliza una máquina virtual.
\item WSL 2 ejecuta un kernel real de Linux mediante una VM ligera.
\item Utiliza Hyper-V como tecnología de virtualización.
\end{itemize}
\end{frame}

\section{WSL como caso de estudio (Sección)}
\label{sec:org5cb2d88}

\begin{frame}[label={sec:orge51c5a6}]{Windows Subsystem for Linux (WSL) (G9, 11, 301)}
\begin{itemize}
\item WSL es una característica de Windows que permite a los desarrolladores ejecutar un entorno GNU/Linux (herramientas CLI, utilidades y aplicaciones) de forma nativa.
\item Evita el sobrecoste de recursos y los tiempos de arranque lentos asociados a una máquina virtual tradicional completa.
\item Facilita el desarrollo cruzado sin necesidad de reiniciar la computadora (dual-boot).
\end{itemize}
\end{frame}

\begin{frame}[label={sec:org3829908}]{WSL1 vs WSL2: arquitectura (G9, 11, 303)}
\begin{columns}
\begin{column}{0.4\columnwidth}
\begin{itemize}
\item \alert{WSL1:} Capa de traducción de llamadas al sistema (Linux a NT). No hay kernel real.
\item \alert{WSL2:} Máquina virtual ligera altamente optimizada.
\item Ejecuta un kernel de Linux completo mejorando el rendimiento de E/S.
\end{itemize}
\end{column}

\begin{column}{0.6\columnwidth}
\begin{center}
\includegraphics[width=\textwidth]{images/arquitectura_wsl.png}
\end{center}
\end{column}
\end{columns}
\end{frame}
\begin{frame}[label={sec:org6c8180d},fragile]{Integración con el sistema de archivos Windows (G9, 11, 305)}
 \begin{itemize}
\item WSL permite acceder a los discos de Windows (C:, D:) desde Linux montándolos automáticamente en el directorio \texttt{/mnt/}.
\item WSL2 utiliza un disco duro virtual (VHD) con formato nativo \texttt{ext4} para el sistema de archivos raíz de Linux.
\item El acceso y la transferencia de archivos cruzada entre ambos sistemas operativos se realiza mediante el protocolo de red 9P.
\end{itemize}
\end{frame}

\begin{frame}[label={sec:org1e9e982}]{WSL y memoria virtual (G9, 11, 307)}
\begin{itemize}
\item A diferencia de las VMs de Tipo 2 tradicionales que reservan y
bloquean un fragmento estático de RAM, la VM de WSL2 asigna y libera
memoria dinámicamente según la demanda.
\item Si Linux libera memoria de su caché interna, WSL2 se encarga de
devolver esa memoria RAM física al Host (Windows) para que otras
aplicaciones de escritorio puedan utilizarla.
\end{itemize}
\end{frame}
