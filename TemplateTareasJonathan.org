* Objetivos de Aprendizaje

- Analizar la arquitectura original de WSL 1 mediante traducción de
  llamadas.
- Entender el cambio de paradigma en WSL 2 hacia la virtualización
  ligera con un kernel nativo.

* Notas de Cornell

#+attr_latex: :environment longtable :align |p{4.5cm}|p{10.5cm}|
| *Ideas Clave / Preguntas* | *Apuntes de Clase*                                                                                                                                                  |
|---------------------------+---------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| *¿Qué es WSL?*            | Subsistema de Windows para Linux. Permite ejecutar herramientas de Linux de forma nativa en Windows.                                                                |
| *Arquitectura WSL 1*      | Utiliza una *Capa de Traducción*. No tiene un kernel de Linux real instalado.                                                                                       |
| *Problema de WSL 1*       | Intercepta las llamadas al sistema (syscalls) de Linux y las traduce al Kernel de Windows. Esto genera cuellos de botella y lentitud en lectura/escritura de disco. |
| *Arquitectura WSL 2*      | Abandona la traducción. Utiliza una *Máquina Virtual Ligera* (Utility VM) basada en Hyper-V.                                                                        |
| *Kernel Nativo*           | WSL 2 corre un Kernel de Linux real, completo y optimizado directamente en la VM, eliminando la necesidad de traducir llamadas.                                     |
| *Beneficios de WSL 2*     | Compatibilidad total con aplicaciones complejas (como Docker) y un rendimiento de sistema de archivos inmensamente superior.                                        |

* Resumen
WSL ilustra la evolución del soporte inter-sistemas. WSL 1 intentó
ejecutar binarios de Linux interceptando y emulando sus llamadas de
sistema, lo que penalizaba el rendimiento. WSL 2 resolvió este
problema de arquitectura al integrar un hipervisor ligero que corre un
kernel real de Linux, ofreciendo ejecución nativa, máxima velocidad de
disco y 100% de compatibilidad.
